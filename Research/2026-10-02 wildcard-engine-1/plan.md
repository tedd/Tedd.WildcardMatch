# Direct wildcard engine

Baseline revision: 0f0784d. Date: 2026-10-02, Europe/Oslo.

Implement a dependency-free netstandard2.0 matcher under the existing WildcardMatch API. Preserve the Regex engine as WildcardMatchRegex. Preserve exact UTF-16 wildcard semantics, literal backslashes/metacharacters, final-LF dollar anchoring, Singleline, culture case groups, options validation, constructor culture capture, timeout range/exception payload, and concurrent instance reuse. Regex translation is diagnostic-only in the direct engine, lazily generated on property access or timeout.

Mechanisms: iterative latest-star retries instead of Regex backtracking; anchored fixed prefix/suffix checks to prevent common adversarial rescans; bulk ordinal comparison for literal patterns; call-local constant-memory state and amortized timeout checks; preserve Regex lowercase case groups rather than applying collation or uppercasing. Worst-case retry work remains polynomial O(inputLength * patternLength); this is not a universal linear-time claim. Multiline numeric casts have a separate line-start search path with an additional input-length factor in its worst-case bound.

Correctness: independent original Escape/Replace Regex oracle, independent dynamic-programming oracle, exhaustive patterns over ab*?LF through length five versus inputs over abLF through length four, Singleline on/off, all 32 declared option combinations in four cultures, numeric Regex flags 0..2048, seeded UTF-16 fuzz including generated matches and near misses, long segment fuzz, all BMP casing candidates, isolated surrogates, supplementary/combining characters, empty/long inputs, null precedence, timeout boundaries/payload, concurrent use, and allocation accounting.

Test-oracle repairs: one handwritten expected case (abaac, *a?ac) was false; corrected before acceptance. Old xUnit hashes both isolated surrogate strings identically; an explicit case ID prevents silently skipping either case. Interpreter Regex can time out on long arbitrary star patterns; long fuzz uses the preserved Regex engine with NonBacktracking while the DP oracle remains independent. The initial Regex timeout fixture was optimized to immediate failure by its required-literal scan; use a separate repeated-star/order-failure fixture to test that engine's timeout payload. Failed test logs are retained under raw/archive.

Performance protocol: actual public direct/Regex APIs from the same netstandard2.0 build; 13 fixtures spanning empty/literal/simple/miss/escaping/Unicode/newline/multiline/long/dense/complex; static, reused, and construction-plus-one-match. Three fresh processes pinned to logical CPU 30, .NET 10.0.12, SDK 10.0.401, runtime-default tiering/PGO and GC. Joint warmup 200ms per case/mode; common iteration counts calibrated on Regex to >=20ms; nine ABBA/BAAB blocks with two samples per engine/block, no sample removal or overhead subtraction. Shorter direct blocks are a limitation; measured results include equal delegate/loop overhead. Keep 54 samples per engine/case/mode and managed bytes/call. No universal speedup or cross-epoch claim.

All builds/tests/benchmarks run through the fixed OS-backed performance lock. Driver contents have been inspected: only local filesystem/build/test/string computation, no database/external application writes. Disposable files stay under D:\Workspaces\AI\wildcard-engine. Concurrent repository packaging/benchmark/site edits are outside this task and excluded from staging.

Reference contracts: https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Text.RegularExpressions/src/System/Text/RegularExpressions/RegexCaseEquivalences.cs and Regex.cs. Runtime-specific Unicode casing differences remain a compatibility concern; executing differential checks, rather than presumed ordinal case equivalence, determine correctness on tested runtimes.

## Bulk literal-run follow-up and build epoch

The initial engine beat ordinary Regex static/reused workloads but compiled Regex was substantially faster on long literal suffixes, dense question-mark patterns, Unicode case folding, and complex reused patterns. Extend only case-sensitive patterns of length at least 32 with library IndexOfAny/LastIndexOfAny and CompareOrdinal for fixed literal prefix/suffix runs. Preserve scalar handling for short patterns, question marks, stars and ignored case. All initial raw samples and source are retained in raw/initial-engine. No universal linear complexity or superiority to compiled Regex is claimed.

Concurrent authorized work changes production targets to netstandard2.1/net10.0/net11.0 and tests to net8.0/net10.0/net11.0. SDK 10 could not build the new net11 target; that failed driver build is retained. Final driver uses installed SDK 11.0.100-rc.1.26425.128 and actual current targets. Timed net10.0 workers still execute .NET 10.0.12, now referencing the package's net10.0 assembly. This is a new build epoch; initial-versus-final direct timings do not isolate the bulk change. Final adoption is evaluated against contemporaneous Regex controls in the same build. Release/Debug checks cover the actual test targets, with additional net9.0 checks via a staged test-project override. No repository target or SDK configuration is overwritten by this task.

## Final compatibility and acceptance

Differential testing exposed .NET 11's AnyNewLine option and its IgnorePatternWhitespace treatment of unescaped vertical tabs. The direct engine handles Unicode newline sequences and normalizes vertical tabs only for the relevant runtime/flag combination. Numeric option validation now covers -1 through 4096 against the running Regex implementation. Timeout exceptions retain the original pattern's translated diagnostic string.

Final Release and Debug suites pass on .NET 8 and 10 (209 tests each) and .NET 11 (212 tests); the additional .NET 9 Release suite passes all 209 tests. Exhaustive ordinary matching covers 945,252 pattern/input combinations per suite, alongside seeded Unicode fuzz, long-pattern fuzz, BMP case equivalence and .NET 11 Unicode-anchor coverage. The comparative package corpus also validates successfully.

Final paired measurements retain 54 samples per engine/case/mode. Simple static matching improves from 401.2 to 58.1 ns; complex static matching from 52,768.9 to 839.6 ns. Every measured default direct static/reused sample records zero managed allocation. Compiled Regex remains faster for several reused patterns, including case-insensitive, dense, Unicode and complex cases. The report records these regressions and rejects universal superiority. The requested engine rewrite is accepted on correctness and contemporaneous integrated measurements; this does not represent an exhaustive catalogue search or an isolated measurement of the bulk-path component. Reproduce compiled controls separately with the driver's compiled phase, as specified in the report.
