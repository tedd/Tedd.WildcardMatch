Protocol and applicability

Baseline wildcard revision: 4f1a8b7442168698a3ee936978d504f2b3a8fe32. DotNetLab checkout: ab314bd. CPU: AMD Ryzen 9 5950X. Windows x64 build 26200. SDK 10.0.402; benchmark runtime CoreCLR 10.0.12. Both normal builds embed the selected library source in the entry assembly, with byte-identical managed harness dependencies and runtime settings. This follows the service’s entry-assembly treatment boundary.

Pattern: * + 70 lowercase a units + ?b*. Each batch cycles four fixed inputs. Dense shapes contain long repeated anchors with successful and failing suffixes; ordinary and newline distributions guard fast rejection and LF behavior. See the complete workload and independent Regex oracle.

Exploration: ten randomized paired blocks in one process, explicitly descriptive. Confirmation: ten randomized paired fresh-process blocks for each shape, two warm-up batches, fixed seed 20261015, no exclusions, replacements, or sample expansion. Operations per batch: dense 512, ordinary 300000, newline 1000. Four comparisons share family alpha 0.05, giving local alpha 0.0125. Dense benefit requires ratio below 0.99; ordinary/newline guardrails use ±5%. The ordinary plan’s isolated promotion flag is false because equivalence is not a primary improvement; the combined adoption decision treats it as a guardrail.

Fresh processes reset managed state and PGO. Host load, affinity, thermal state, and frequency were uncontrolled; no exclusive host lock was held. Statistical intervals depend on the declared paired-session assumptions. These results cover the specified matching calls, not construction, arbitrary patterns, other runtimes’ performance, or application throughput.

Correctness and disposition

Complete wildcard suites passed: .NET 8: 242; .NET 10: 242; .NET 11: 245. New regressions vary rejected anchors, LF placement, final LF, multi-segment patterns, Singleline and string/span entry points. The .NET 8 suite exercises the .NET Standard fallback. Existing analyzer and legacy test-package warnings remain in the test transcript.

Retain the incremental frontier. No conclusion is drawn about overall optimality: anchor search and segment validation remain possible adjacent costs. SIMD changes, parallelism and offload were not pursued because this investigation targeted repeated logical work without changing representation or concurrency. The optimization and research record are integrated into the original wildcard main; the reusable MCP exerciser is integrated into DotNetLab main. No remote push or publication.
